# GitHub 自动更新（开发分支）

官方版本来源：`Zc345370669/XG-Launcher` 的 GitHub Releases。无需自建服务器，也不使用个人访问令牌。

## 使用

- 桌面启动时检查新版本；确认后下载、校验并安全退出，独立更新器替换 EXE 后重新打开。取消不会替换文件。
- 设置 → 关于：点击版本号手动检查，没有额外检查按钮。
- 下载弹窗显示实际字节数、进度以及校验状态。更新包错误、网络错误或校验失败不会修改安装文件。
- 正在下载的可恢复任务保存后挂起；原子加载器步骤等待安全完成。运行中的游戏不会被强杀，需要先关闭游戏再更新。
- 更新写入白名单仅有 `XGLauncher.exe`。账号、设置、存档、模组、光影、Java 和游戏资源均不属于更新内容。旧程序先备份，替换或启动失败时回滚并尝试打开旧程序。

## 维护者发布步骤（手动）

1. 将项目版本改为高于当前版本的新 SemVer，例如 `0.1.1-alpha`，并同步显示版本和发行说明；不得用相同版本标签冒充更新。
2. 通过 PR 的 Windows 构建、测试、公开源码安全扫描和许可检查后，再审核合并。本工作流不会自动合并、创建 Tag 或 Release。
3. 从通过检查的提交下载 Actions 构建产物，取 `XGLauncher-portable-win-x64.zip`。ZIP 内必须只有 `XG-Launcher/XGLauncher.exe`。
4. 在官方仓库创建对应 Tag 的 GitHub Release，上传上述 ZIP；测试版勾选预发布，完成后人工发布。不要上传源码缓存或用户数据。
5. 检查 GitHub API 返回该资源的 `digest`（`sha256:` 加 64 位十六进制）和实际文件大小。缺少散列、非官方路径、草稿及不兼容格式不会作为可安装更新提供。

稳定版本只接受稳定 Release；Alpha/Beta/RC 客户端也可接受更高的预发布版本。首次引入此协议之前的旧客户端需要手动升级一次。

## 安全与许可

仅请求官方公开元数据；下载前检查每次重定向的 HTTPS 主机，限制大小并验证 SHA-256，防止路径穿越、重复文件、目录链接和用户数据覆盖。暂存和实际替换各自重新验证 ZIP。SHA-256 校验不等于发布者代码签名，官方 GitHub 仓库与发布权限仍需维护者保护。

单 EXE 内嵌独立更新器、MIT、Lucide ISC/适用 Feather 许可、全部现有第三方声明、历史授权证据及原生组件对应源码材料。关于页可以离线查看许可并导出完整合规 ZIP；没有删除或把第三方授权改为 MIT。

Windows 自动测试与真实用户桌面验收是两类证据。CI 不代表已验证微软应用审核、真实公网下载、UAC、防病毒软件、Windows 10/11 桌面交互或更新中断电。微软认证原有 HTTP 403 仍按真实结果反馈。


## 更新结果与故障验证

独立更新器通过固定枚举回执把结果传给重新打开的启动器。启动器只读取下载暂存根目录内 `GUID/apply.json.result`，拒绝目录链接、超长内容、任意路径和异常正文。成功后无需额外确认；失败时显示可操作的提示，避免启动后立即重复弹出同一更新。

事务只在 EXE 真正替换成功后登记回滚；旧 EXE 被占用且未发生替换时，不再尝试覆盖它。回滚使用同目录临时文件原子替换，恢复失败时保留备份。提交后的临时文件清理失败不会把成功更新误报为失败。

Windows 发布检查使用独立测试 EXE 的启动标记，验证成功更新、错误散列、替换后启动失败的真实回滚、EXE 文件占用、父进程退出等待和用户数据写入拒绝。测试 EXE 不进入发行包。进程测试不等于 Windows 桌面交互验证，也不保证断电时的自动恢复。
